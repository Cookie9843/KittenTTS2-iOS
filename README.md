# KittenTTS2-iOS

Offline text-to-speech for **iPhone and iPad** (iOS 16.4 or later). After a model is on your device, speech is generated on the device, with no account and no cloud service.

- **KittenTTS 2** (best quality): 48 preset voices, several languages, and voice cloning from a short recording.
- **KittenTTS 0.8** (small and fast): the original Nano / Micro / Mini models with 8 voices and a speed control.

> **AI disclaimer.** This app and repository were created with substantial AI assistance (GitHub Copilot and OpenAI models). Final product decisions and testing were done by the repository owner, [@Cookie9843](https://github.com/Cookie9843). The model weights are **not** AI-created by this project; they come from the upstream KittenTTS / Stellon Labs work (and the community conversion linked below). The speech runtime is upstream [audio.cpp](https://github.com/0xShug0/audio.cpp) (via a community fork, see [Provenance](#license-and-provenance)). Neither is AI-generated by this repository.

## 1. Get the app and install it

**Download:** go to the **[Releases page](https://github.com/Cookie9843/KittenTTS2-iOS/releases)** and download `KittenTTS-<version>-unsigned.ipa` from the newest release (a `.sha256` file is next to it so you can check the download). Releases are created from version tags named `v…` (for example `v1.0.0`).

**The IPA is unsigned.** iOS will not install it as it is. You must sign it yourself with your own Apple ID or developer certificate, using any signing/sideloading tool you trust, and install it on your own device. Signing is your responsibility; the project does not sign, host or distribute signed builds. Nothing in the app depends on one specific tool.

The only build meant for you is the **Release IPA** (`KittenTTS-<version>-unsigned.ipa`) on the Releases page: the full app with the real speech engine linked in. Install it after you sign it.

Workflow runs of "iOS audio.cpp runtime + full app IPA" also attach an unsigned full-app IPA as a temporary build artifact (artifact `KittenTTS-unsigned-ipa`) for development; use the Releases page for normal installs.

The bundle identifier is `com.cookie9843.KittenTTS2App`; your signing tool may change it to one you own.

## 2. Prerequisites

- An **iPhone or iPad** running iOS 16.4 or later that you can sign/sideload to, and a way to sign an IPA (free Apple ID or paid developer account; free profiles expire and need re-signing, which is a property of Apple's signing rules, not of this app).
- **Storage:** KittenTTS 2 is a **3.28 GB** download (3,282,123,776 bytes). Keep roughly **3.5 GB free** while downloading (the file plus working space); importing a file you already have needs a second full copy while it is verified, so about the same again. KittenTTS 0.8 models are about 25–80 MB.
- **Memory:** KittenTTS 2 is memory-mapped, but generation still needs a lot of RAM. It was observed working on one iPad with about 2.5 GB reported available to the app. Devices with less free memory may fail with an out-of-memory error (see [Troubleshooting](#7-troubleshooting)); the app shows its own estimate in **Models → Advanced: memory and diagnostics**. Close other apps first.
- **Wi-Fi** for the first download. The KittenTTS 2 download asks whether mobile data may be used; choose Wi-Fi only unless you have a large data plan.

## 3. First launch and setup

The app has four tabs: **Speak**, **Voices**, **Models** and **History**. Start in **Models**.

### Option A: KittenTTS 2 – download

1. **Models → KittenTTS 2 → Download from Hugging Face (3.28 GB)**.
2. Read and accept the short license notice, and choose **Download on Wi-Fi only** or **Allow mobile data too**. The dialog tells you how much storage is still needed.
3. Wait for download, verification (SHA-256) and install. You can leave the screen, but keep the app open; downloads do not continue after you quit the app.
4. The model page shows **Downloaded from Hugging Face … Verified against the published checksum.**

### Option B: KittenTTS 2 – import a GGUF you already have

1. **Models → KittenTTS 2 → Import a KittenTTS 2 file from Files…** and pick the `.gguf` file.
2. Only the audio.cpp single-file package is compatible: [`dignome/kitten_tts2`](https://huggingface.co/dignome/kitten_tts2), file `kitten-tts2-native-q8-multilingual.gguf` (GGUF architecture `audiocpp`, family `kitten_tts2`). Other GGUF files are rejected with an explanation. KittenML's own `model-tq2_1.gguf` uses a different runtime and is **not** supported.
3. The file is checked, copied in chunks to a staging folder and only then moved into place. If it has the published size, its SHA-256 must match; a different but compatible export is accepted and labelled as not checksum-verified.
4. If an import fails or you cancel it, your existing model is left exactly as it was and you can simply try again.

### Option C: KittenTTS 0.8 – download or import

1. **Models → KittenTTS 0.8**, choose **Nano (fp32)**, **Nano (int8)**, **Micro** or **Mini**, then **Download**. Files come from the official `KittenML/kitten-tts-*-0.8` repositories on Hugging Face (links are in the Models tab).
2. Or use **Import files you already have…** and pick the `.onnx` model and its `voices.npz` together.
3. The first generation may also fetch small phonemizer data files if they are missing.

## 4. Using the app

### Choosing a voice
On **Speak**, pick the engine (KittenTTS 2 or 0.8), then choose a preset voice from the **Voice** dropdown. KittenTTS 2 has 48 presets; voices named after a language are multilingual presets for that language. KittenTTS 0.8 has 8 voices and a speed slider.

### Generating speech
Type or paste text on **Speak** and tap **Speak**. The first KittenTTS 2 run loads the model and can take 10–30 seconds. Generation cannot be interrupted once started. The result plays automatically and is saved to History.

### Cloning a voice (KittenTTS 2)
On the **Voices** tab (cloning section):

1. Add a reference clip of **1–30 seconds** of clear speech: **Record with microphone**, or **Choose an audio file…** from Files. Use a quiet place and a single speaker.
2. The app drafts a transcript of the clip with Apple's **on-device** speech recognition. You can also type it yourself, in which case your text is never overwritten unless you tap Transcribe again.
3. **Review the transcript before generating.** Automatic recognition can mishear words and often **leaves out or misplaces punctuation**. Play the reference clip and correct **both the wording and the punctuation** so the text matches what is said, then tap **Words and punctuation are correct** (or just edit the text). A recognized transcript cannot be used until you have edited or confirmed it. A wrong transcript makes the cloned voice worse.
4. Turn on **Speak with my cloned voice**, then tap **Speak** on the Speak tab.

If on-device recognition is not available for your language, the app says so and you type the transcript yourself. Your recording is never uploaded.

### Playback, history and export
**History** lists everything you generated. Use **Play** on an item to play it; **Save or share WAV** / **Export WAV** exports it; swipe to **Delete** one item, or **Clear all**. History is stored on the device.

## 5. Managing and removing models

Everything is in **Models**.

| Action | KittenTTS 2 | KittenTTS 0.8 |
| --- | --- | --- |
| Pause a download | **Pause** keeps the partial file; **Resume download** continues from the same byte (verified again by size and SHA-256 at the end). | Not available: the original downloader cannot pause or resume. |
| Cancel a download | **Cancel and remove partial download** (or **Discard partial download** after a pause). | **Cancel download and remove partial files.** The file already in flight finishes first (25–80 MB), then everything from that download is removed. |
| Cancel an import | **Cancel import** leaves your current model untouched. | **Cancel import.** |
| Free memory | **Free memory** unloads the model from RAM without deleting it. | – |
| Remove a model | **Remove from this device** unloads the engine first, then deletes the downloaded file, any imported file and any partial files. | **Remove from this device** removes the selected size only. |

Removal is disabled while that model is loading, generating, downloading or being imported.

## 6. Permissions and privacy

- **Microphone**: only when you record a cloning reference.
- **Speech recognition**: only when you tap Transcribe (or when a new reference clip triggers the draft). Recognition is forced on-device; the app never sends your recording to a server. If on-device recognition is unavailable for a language the app tells you and asks you to type the text.
- **Files**: through the system picker only, and the app holds access to a picked file only while it reads it.
- **Network**: used only to download models and small data files from Hugging Face when you ask. Text you synthesize and your recordings stay on the device. There is no analytics or account.

## 7. Troubleshooting

| What you see | What to do |
| --- | --- |
| *Out of memory* / `std::bad_alloc` / *failed to allocate … buffer* / *failed to initialize … graph context* | The device ran short of memory. Close other apps, then tap **Speak** again: a failed request makes the app rebuild its engine session, and the retry does not need an app restart. If it keeps happening, use **Models → KittenTTS 2 → Free memory**, retry, and share **Advanced: memory and diagnostics** when reporting it. Very short free-memory budgets may simply not be enough for voice cloning. |
| *Not enough free storage* when downloading or importing | The message states how much is needed and available. Free that much space and retry; a partial download only needs the missing bytes. Your existing model is not changed. |
| *Unsupported GGUF* / *not a compatible KittenTTS 2 package* | Use `kitten-tts2-native-q8-multilingual.gguf` from `dignome/kitten_tts2`. KittenML's TQ2_1 GGUF and other architectures are not compatible. |
| Import failed | The message names the step that failed and shows the system error code, free storage and available memory. The installed model is left intact, the temporary copy is removed, and **you can pick the file again straight away without restarting the app**. If it says a file is in iCloud, download it in Files first. If another task is running, wait for it or cancel it. Please include the full message when reporting a problem. |
| Download stopped (network) | Your progress is kept; tap **Resume download**. |
| *The downloaded file failed its integrity check* | The partial file was discarded; download again. |
| *Automatic transcription unavailable* | On-device recognition is not offered for that language/device, or permission is off (Settings → Privacy & Security → Speech Recognition). Type the transcript yourself. |
| *Microphone access is off* | Enable it in Settings → Privacy & Security → Microphone, or choose an audio file instead. |
| *This build does not include the KittenTTS 2 speech engine* | You installed a build without the speech engine. Install the release IPA instead. |
| App closed by iOS during generation | Usually memory. The next launch shows a note about the previous run under Advanced diagnostics. |

## 8. What has and has not been verified

- **Automated (CI and `swift test`, Linux):** download manifest, resume and SHA-256 verification, atomic install, import validation and recovery after failed/cancelled imports, storage rules, per-operation status messages, clone input rules, transcript review rules, legacy model delete/cancel cleanup, and the native bridge session lifecycle against a fake audio.cpp interface. The full-app IPA builds and the real runtime symbols are linked (checked in CI).
- **Observed by the owner on their own devices:** KittenTTS 2 load and preset synthesis (one iPad, iPad16,5 on iOS 27.0: load 10.55 s, 75,360 samples at 24 kHz in 7.42 s, 2.52 GB reported available), voice cloning, GGUF import, storage checks and KittenTTS 0.8. Exact devices/OS versions for the other flows were not recorded.
- **Not verified:** other devices, memory sizes, signing methods or locales; every preset voice; repeated-generation stability on all hardware; the new KittenTTS 0.8 cancel/remove controls, the transcript wording and the import changes on a real device. CI cannot prove on-device inference. macOS and Android are not supported.

## Building from source and releases (maintainers)

Requires macOS with Xcode for the app; `swift test` runs on macOS or Linux.

```sh
swift test                                  # KittenCore: formats, validation, downloader, importer, storage, status, history, WAV
scripts/run_bridge_lifecycle_test.sh        # native bridge session policy against a fake audio.cpp ABI (no model)
for f in scripts/*.sh; do bash -n "$f"; done   # shell syntax
scripts/build_audiocpp_ios.sh               # builds the audio.cpp kitten_tts2 runtime for iOS arm64 (sets up $WORK)
WORK=… scripts/build_app_ipa.sh             # full unsigned IPA linked against that runtime; fails if native symbols are missing
```

Workflows:

- `workflow_guard.yml`: checks that release/CI workflows still build the real audio.cpp runtime and that no UI-only build exists.
- `ios_audiocpp_kitten2.yml`: runs `swift test` and the bridge lifecycle test, builds the runtime and the **full** app IPA, verifies the linked symbols, uploads the temporary artifact `KittenTTS-unsigned-ipa`.
- `release.yml`: runs on tags matching `v*`.

### Publishing a release

1. Make sure `main` is green.
2. Create and push an annotated version tag **on a commit in `main`**, for example `git tag -a v1.0.0 -m "v1.0.0" && git push origin v1.0.0`. Tags containing a hyphen (`v1.0.0-rc1`) are published as pre-releases.
3. `release.yml` runs `swift test` and the bridge lifecycle test, builds the real runtime and the full app, **refuses to continue** unless `_audiocpp_model_load` / `_audiocpp_session_run` and the bridge symbols are in the packaged binary and no `.gguf` is inside, and then creates the GitHub Release for the tag with `KittenTTS-<tag>-unsigned.ipa` and its `.sha256`. The UI-only build is never attached.
4. Edit the release notes if you like. Users sign the IPA themselves; the project does not.

Running the workflow manually (`workflow_dispatch`) only builds and checks; it publishes nothing.
